# 실험13 — late fusion 2-way 의 "묶음 조합"

> **한 줄 결론:** 세 모달리티를 다 쓰는 2-way 구조에서 **임상+판독지를 묶는 것이
> 유일하게 옳은 선택**이다. OS 에서 다른 두 묶음보다 확실히 높고(Δ−0.033/−0.049,
> 5 fold 중 5개·4개에서 우세), PFS 에서는 세 묶음이 구분되지 않는다.

## 왜 이 실험을 했나

채택 모델(late fusion 2-way)은 세 모달리티를 **다 쓰되** 그중 둘만 한 모델로
묶어서 학습하고 나머지 하나는 따로 학습해 CoxPH 로 결합한다. 묶는 조합은 셋뿐이다.

| | 묶음 축 | 남은 축 | 상태 |
|---|---|---|---|
| **G1** | concat[임상+판독지] | 영상 단독 | **채택** (`RESULTS_TABLE_final.md` 표3-1 (c)) |
| **G2** | concat[임상+영상] | 판독지 단독 | 실험13에서 측정 |
| **G3** | concat[판독지+영상] | 임상 단독 | 실험13에서 측정 |

논문 리뷰어의 예상 질문 — "왜 하필 임상과 판독지를 묶었나" — 에 답하려면 G1 을
나머지 둘과 같은 조건에서 비교해야 한다. 세 셀은 **모달리티 집합(3개)도 같고
융합 구조도 같다**. 바뀌는 건 묶음 하나뿐이라 성능 차이를 묶음 선택에 귀속시킬 수
있고, "영상을 뺐다"는 오해도 함께 차단된다.

기존 표3-1 의 (a) early concat = *셋 다* 묶음, (b) late 3-way = *아무것도* 안 묶음
이 이 축의 양 끝이다. G1~G3 가 그 사이를 채워 다섯 셀이 완성된다.

## 결과 (RadBERT · `brain_meta` 수정 후 · seed 42 · bs32/ep60)

### 결합 성능

| 묶음 | OS | PFS |
|---|---|---|
| **G1  [임상+판독지] + 영상 (채택)** | **0.7224 ± 0.0332** | **0.6470 ± 0.0286** |
| G2  [임상+영상] + 판독지 | 0.6894 ± 0.0337 | 0.6445 ± 0.0414 |
| G3  [판독지+영상] + 임상 | 0.6733 ± 0.0469 | 0.6407 ± 0.0383 |

G1 을 기준선으로 한 fold 대응 검정:

| 묶음 | 타깃 | Δ | G1 보다 나은 fold | paired t p | wilcoxon p |
|---|---|---|---|---|---|
| G2 | OS | −0.0330 | 0/5 | **0.0099** | 0.0625 |
| G3 | OS | −0.0491 | 1/5 | **0.0459** | 0.1250 |
| G2 | PFS | −0.0025 | 2/5 | 0.8752 | 1.0000 |
| G3 | PFS | −0.0063 | 3/5 | 0.7877 | 1.0000 |

(n=5 fold 라 wilcoxon 양측 p 는 최소 0.0625 — 0.05 를 원리적으로 못 넘는다. 참고용.)

### 축 성능 (결합 전)

| 축 | OS | PFS |
|---|---|---|
| `clin_only` 임상 단독 | 0.6388 ± 0.0443 | 0.6223 ± 0.0366 |
| `report_only` 판독지 단독 (RadBERT) | 0.6685 ± 0.0370 | 0.6354 ± 0.0420 |
| `clin_image` concat[임상+영상] | 0.6710 ± 0.0279 | 0.6274 ± 0.0323 |
| `report_image` concat[판독지+영상] | 0.6656 ± 0.0532 | 0.6279 ± 0.0446 |

## 해석

**1. OS 에서 묶음 선택은 실제로 성능을 가른다.** G1 이 G2 보다 +0.033 높고 5 fold
**전부**에서 우세하다(p=0.010). G3 와는 +0.049 차이다(4/5, p=0.046). 채택한 묶음은
임의의 선택이 아니다.

**2. 영상은 누구와 묶어도 손해다.** 묶음 축을 다섯 셀로 늘어놓으면 OS 순서가 이렇다:

```
G1 [임상+판독지]+영상   0.7224   <- 영상만 따로
(b) 아무것도 안 묶음     0.7045
G2 [임상+영상]+판독지   0.6894   <- 영상을 묶음
(a) 셋 다 묶음          0.6879   <- 영상을 묶음
G3 [판독지+영상]+임상   0.6733   <- 영상을 묶음
```

**영상을 어떤 모달리티와 함께 학습시키든 아무것도 안 묶은 (b) 보다 떨어지고,
영상을 떼어낸 G1 만 (b) 를 넘는다.** 즉 "묶기"가 이득인 조합은 임상+판독지 하나뿐이다.
이건 새로운 현상이 아니라 `RESULTS.md` §9.4 에서 이미 정량화된 기전 — concat 구조에서
영상이 최종 위험점수의 발언권을 70~80% 독점해 tabular 신호를 덮는다 — 의 직접적인
귀결이다. 실험13은 그 기전을 **묶음 조합이라는 독립적인 축에서 재확인**한다.

**3. PFS 에서는 세 묶음이 구분되지 않는다.** Δ가 −0.003/−0.006 이고 p 가 0.79~0.88 이다.
이 역시 기존 결론과 일치한다 — `RESULTS.md` §10 에서 **영상에는 PFS 정보가 없다**고
확인됐으므로, 영상을 어디에 배치하든 PFS 가 달라질 이유가 없다. 묶음 선택의 근거는
OS 에서 나오고, PFS 에서는 최소한 손해가 아니다.

## 누수 방지

새로 짠 학습·결합 코드가 없다. 전부 검증된 경로를 상속해서 쓴다.

- **fold별 인코더 적합** — `sclc.encoders` 의 `ReportEncoder` 계약(train fold 환자로만
  fit). 학습 전 `preflight` 가 fold 마다 실제 feature 행렬을 만들어 폭·분산을 확인한다
  (실측: `report_dim=768`, 5 fold 모두 nonzero 768/768).
- **임상 스케일러 / TF-IDF** — `features.build_fold_multimodal_tabular` 의 train-only 경로.
- **CoxPH 결합** — `sclc.late_fusion.combine_risk_scores`. fold 마다 train 환자의 OOF
  점수로만 적합하고 test 에 적용한다.
- **`brain_meta` 기저시점 누수 수정** — 기본값 `fix_brain_meta=True` 적용.
- 남아 있는 알려진 한계(nested CV 가 아니다)는 G1 과 **동일**하므로 세 셀의 비교는
  공정하다. 설명은 `src/sclc/experiments/fusion.py` docstring.

### 내장 재현 대조

`clin_only` 축은 실험12가 같은 조건(RadBERT/bs32/ep60/seed 42)으로 이미 측정했다.
이 축을 **맨 먼저** 돌려 값이 어긋나면 비싼 영상 축 두 개를 돌리기 전에 경고가 뜬다.

| 타깃 | 실험12 | 실험13 | 판정 |
|---|---|---|---|
| OS | 0.6387690795698175 | 0.6388 | MATCH |
| PFS | 0.6222844400296995 | 0.6223 | MATCH |

fold 값까지 일치했다. 학습 경로가 실험12와 동일하다는 뜻이므로 나머지 축 결과도
같은 조건에서 나온 값이다.

## 영상의 학습 조건에 대하여 (설계상 불가피한 비대칭)

G1 에서 영상은 **독립 축**이라 영상 arm 표준 조건(bs16/ep30)으로 돌고, G2·G3 에서
영상은 묶음 **안에** 있어 묶음 축의 조건(bs32/ep60)을 따른다. 이 차이는 교란이 아니라
**처치 그 자체**다 — "영상을 따로 학습하느냐 같이 학습하느냐"가 곧 이 실험이 재는
것이기 때문이다. 영상을 묶으면 그 순간 공동 스케줄을 따를 수밖에 없다.
(실험3의 `clin_image` 도 같은 bs32/ep60 이다.)

## 파일

| 파일 | 역할 |
|---|---|
| `exp_grouping.py` | 축 4개 학습 → CoxPH 결합 2개. `LateFusionExperiment` 상속 |

```bash
python experiments/실험13_융합묶음_조합비교/exp_grouping.py --target os
python experiments/실험13_융합묶음_조합비교/exp_grouping.py --target pfs
python experiments/실험13_융합묶음_조합비교/exp_grouping.py --preflight_only   # 수 초
```

산출물: `outputs/fusion_grouping/results_{os,pfs}.json` (축은 `axes`, 결합은
`combinations` 키). GPU 기준 타깃당 약 25분 — 영상이 들어간 축 두 개가 대부분이다.

`--encoder tfidf` 로 인코더를 바꿔 돌릴 수 있지만, 표3-1·표3-2 는 RadBERT 로 조건이
통일돼 있으므로 기본값을 그대로 쓴다 (인코더를 바꾸면 내장 재현 대조는 자동으로
건너뛴다).
