# 실험10 — 영상 단독 난수대조 검정

**묻는 것:** 영상 단독 C-index(OS 0.6570 / PFS 0.6154)는 **우연으로도 나오는 값인가**,
그리고 우연이 아니라면 **그 신호의 정체는 무엇인가**.

## 왜 새 실험이 필요한가

[RESULTS.md §10.4](../RESULTS.md)의 200회 난수대조는 **이미 계산된 영상 OOF 위험점수**를
환자 간에 섞어 tabular 와 CoxPH 가중합한 것이다. 즉 잰 것은 "영상이 tabular **위에**
얹어주는 증분"이며, 영상 단독의 귀무분포는 어디에도 없다. 여기서는 영상 파이프라인
**자체**를 귀무 라벨 위에서 처음부터 재학습시킨다.

## 팔(arm) 구성

| 팔 | 이름 | 하나만 바꾸는 것 | 복제 | 목적 |
|---|---|---|---|---|
| A | `real_baseline` | (없음) 진짜 라벨·seed 42 | 1 | 공개값 재현 확인 = 하네스 검증 |
| B | `real_seeds` | 학습 시드 | 20 | 관측값의 학습잡음 분포 |
| **C** | `perm_null` | **라벨 순열** | **100** | **귀무분포 → 순열 p값** |
| D | `noise_image` | 이미지 → 균일 난수 | 10 | 바닥 점검 (파이프라인 결함/누수 감사) |
| E | `trivial_stats` | CNN 을 뺌 | 1 | **신호의 정체** (종양 vs 촬영 아티팩트) |
| F | `bootstrap` | (재학습 없음) | 2000 | 효과크기 CI, 0.5 배제 여부 |

네 학습 팔은 **완전히 같은 절차**(30 epoch, bs16, lr 1e-4, wd 1e-4, resize 512,
train fold 픽셀 통계, val 최고 체크포인트)를 쓴다. 실험8의 랜덤초기화 백본 대조는
이미 있으므로([RESULTS_image_cph.md](../실험8_영상단독_고전CoxPH/RESULTS_image_cph.md))
재실행하지 않고 표에 인용만 한다.

## 무엇을 섞는가

`(days, event)` 를 **쌍으로 묶어** 환자 간 재배치한다. 쌍을 깨면 중도절단 구조가
무너져 인위적 귀무가 되므로 금지. 쌍으로 섞으면 KM 곡선·이벤트 총수·관찰기간 분포가
원본과 완전히 같다. split CSV 는 건드리지 않는다.

- `--scope global` **(주력)** 238명 전체에 순열 하나. 교과서적 순열검정.
- `--scope stratified` event 상태 안에서만 섞어 fold 별 이벤트 수를 보존.

### ⚠️ 왜 global 이 주력인가 — 실측으로 뒤집힌 판단

처음에는 "고정 split 이 event 로 층화(test 이벤트 40/40/40/40/39)돼 있으니 층화
순열이 귀무 분산과 더 정합"이라고 봤다. **E팔로 두 귀무를 실제로 그려 보니 틀렸다.**

| 순열 범위 | OS 귀무 (200회) | PFS 귀무 (200회) |
|---|---|---|
| **global** | **0.4957 ± 0.0291** | **0.4981 ± 0.0278** |
| stratified | 0.5306 ± 0.0236 | 0.5206 ± 0.0247 |

층화 순열은 **환자의 event 비트를 고정**하는데, 이 데이터에서 전역 영상통계는
중도절단 여부 자체를 **AUC 0.637(OS) / 0.631(PFS)** 로 맞힌다. 그 연관이 귀무 안에
그대로 살아남아 중심을 0.53 까지 밀어올린다. 분산은 층화 쪽이 좁지만, **중심이
어긋난 좁은 귀무보다 중심이 맞는 넓은 귀무가 옳다.**

그래서 stratified 는 폐기하지 않고 **더 엄격한 조건부 검정**으로만 쓴다:
"중도절단 여부로 설명되는 몫을 빼고도 영상이 생존시간을 맞히는가?"

복제 r 의 시드는 `42 + 100*r` 이며 순열과 학습 초기화에 함께 쓴다(r=0 이 A팔).
C 가 B 보다 분산이 큰 것은 의도된 것 — 절차 전체의 무작위성이 귀무에 들어가야 한다.

> ⚠️ `core.train.fit()` 안의 `evaluate_c_index(model, train_loader)` 를 속도 때문에
> 빼면 안 된다. `train_loader` 가 `shuffle=True` + `generator` 라 순회할 때마다 RNG 가
> 진행되므로, 빼면 학습 셔플 순서가 달라져 A 와 C 가 **다른 절차**가 된다.

> ⚠️ `num_workers` 도 팔 사이에서 바꾸면 안 된다. 실측 결과 **2와 4는 비트 단위로
> 같지만 0은 다른 값**(OS 0.6467 vs 0.6570)이 나온다. 전 팔이 `num_workers=4` 로
> 통일돼 있으며 각 복제 기록에 값이 남는다.

## 사전 등록 판정 규칙 *(실행 전 확정)*

검정통계량 = 5-fold 평균 C-index. 순열 p = `(1 + #{귀무 ≥ 관측}) / (N+1)`.

| 결과 | 결론 |
|---|---|
| 관측 > 귀무 95분위, p<0.05 | 영상 단독에 **우연 이상의 신호가 있다** |
| 관측이 귀무 95% 구간 안 | 영상 단독은 **동전던지기와 구분 불가** |
| 위와 무관하게 E ≈ A 이면 | 그 신호는 **종양 표현형이 아니라 전역 밝기·대비·크롭 기하로 설명 가능** |

D 가 0.5 에서 유의하게 벗어나면 → 검정 중단, 파이프라인 결함부터 조사.

**§10 과 혼동하지 말 것.** 이 실험은 "영상 **단독**에 신호가 있나"를 묻고, §10 은
"tabular 위에 **증분**이 있나"를 물었다. 둘 다 참일 수 있다 — 영상에 신호가 있어도
그 신호가 임상변수와 중복이면 증분은 0 이다.

## 실행

```bash
# ① 재현 확인 + 신호 정체 (약 10분)
python 실험10_영상단독_난수대조검정/exp_permutation.py --arms A
python 실험10_영상단독_난수대조검정/exp_trivial_stats.py

# ② 파일럿 — 귀무 평균이 0.5 근처인지 먼저 확인 (약 80분)
python 실험10_영상단독_난수대조검정/exp_permutation.py --arms C --replicates 1-10

# ③ 본 실행. 같은 runs.jsonl 에 이어붙으므로 3개 프로세스로 쪼개도 안전
python 실험10_영상단독_난수대조검정/exp_permutation.py --arms C --replicates 11-40 &
python 실험10_영상단독_난수대조검정/exp_permutation.py --arms C --replicates 41-70 &
python 실험10_영상단독_난수대조검정/exp_permutation.py --arms C --replicates 71-100 &
python 실험10_영상단독_난수대조검정/exp_permutation.py --arms B,D

# ④ p값·CI·표·그림 (학습 없음)
python 실험10_영상단독_난수대조검정/analyze.py
```

1회 = 5 fold × 30 epoch ≈ **4분/타깃** (RTX 4070 Ti SUPER 실측). 전체 ≈ 17시간,
3-프로세스 병렬 시 ≈ 6시간. 중단해도 `runs.jsonl` 에 남은 복제는 건너뛰고 이어서 돈다.
체크포인트는 쓸 데가 없으므로 복제마다 즉시 삭제한다.
